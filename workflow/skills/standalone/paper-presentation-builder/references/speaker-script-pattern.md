# Speaker Script Pattern

Use this reference when `slide-script.md` or speaker notes are requested.

## One Slide, One Beat

Each slide note should answer four checks:

| check | pass criteria | failure example |
| --- | --- | --- |
| Opening beat | First sentence states why this slide appears now. | "This slide shows some results." |
| Evidence beat | Note points to the visual/proof object without reading every label. | Reading all bullet text aloud. |
| Interpretation beat | Note says what the audience should conclude. | Leaving the figure to speak for itself. |
| Transition beat | Last sentence prepares the next slide's claim. | Abruptly jumping to a new section. |

## Timing Rules

| slide type | target time | note length |
| --- | --- | --- |
| Title or section divider | 10-20 seconds | 1-2 sentences. |
| Motivation/problem | 45-75 seconds | 3-5 sentences with one concrete setup. |
| Method/framework | 60-120 seconds | 4-7 sentences, paced by visual regions. |
| Result/evidence | 60-120 seconds | 4-7 sentences, one takeaway per plot or panel. |
| Limitation/boundary | 30-60 seconds | 2-4 sentences, direct but not defensive. |
| Takeaway | 30-60 seconds | 2-4 sentences, repeat the contribution in talk language. |

## Chinese-English Switching

- If `deck-brief.md` says English, keep visible text and speaker notes in
  English unless quoting a Chinese source.
- If `deck-brief.md` says Chinese, keep technical terms bilingual only when the
  audience benefits, e.g. "一致性 (consistency)" on first mention.
- If bilingual delivery is requested, use one primary spoken language per
  slide and keep parenthetical translations short.
- Do not leak language instructions such as "explain in Chinese" into visible
  slide text.

## Note Quality Checks

- Score 2 when the note can be spoken naturally without reading the slide.
- Score 1 when the note is correct but too long, too short, or too written.
- Score 0 when the note contradicts the slide, invents a claim, or includes
  production instructions.
